# Git Workflow Documentation

## 1. Git
Git is a distributed version control system used to track changes in source code.

## 2. Branching Strategy
- main: Stable production-ready code.
- dev: Integration and development work.
- feature: New feature implementation.

## 3. Pull Request
A Pull Request (PR) allows developers to propose, review and merge changes into another branch.

## 4. Merge vs Rebase
- Merge combines branches and preserves branch history.
- Rebase moves commits onto another base commit and creates a linear history.

## 5. Conflict Resolution
1. Identify conflicting files.
2. Open and review conflict markers.
3. Select or combine the correct changes.
4. Commit the resolved changes.

## 6. Git Tags
Tags mark specific points in repository history, commonly used for releases.

## 7. Git Stash
Git stash temporarily saves uncommitted changes so another task can be performed.

## 8. Git Ignore
The .gitignore file prevents specified files and directories from being tracked by Git.
